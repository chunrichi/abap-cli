The loop

Your editor is the new SE80.

A change used to mean a GUI tour: find the object, lock it, edit, activate, unlock, find the transport. abap-cli turns that into a file edit and one push.

Without abap-cli SAP GUI

One change, seven context switches.

  1. 01Launch SAP GUI
  2. 02Open SE80 / SE11
  3. 03Find and lock the object
  4. 04Edit in the ABAP editor
  5. 05Save, check, activate
  6. 06Unlock and assign a transport
  7. 07Repeat for the next object
×Every step is a context switch.
With abap-cli terminal

One file, one push.

$ abap pull ZCL_MY_CLASS

✓ 4 files → src/

# edit in any editor

$ abap push src/zcl_my_class.clas.abap

--tr DEVK900001

✓ locked → written → activated → unlocked

$ abap test ZCL_MY_CLASS

✓ 12 tests passed

✓Locks, activation and the transport are handled.

The six-step loop

Every command speaks JSON, so the same loop works for a human and for an agent.

  1. 01

    Pull

    abap pull

    Object → flat AFF files under src/.

  2. 02

    Edit

    your editor

    Any editor, any agent, normal diffs.

  3. 03

    Check

    abap check

    Syntax, ATC and local content before writing.

  4. 04

    Push

    abap push

    Lock, write, activate, unlock in one transaction.

  5. 05

    Run

    abap run

    Classrun or a public static method.

  6. 06

    Verify

    abap test

    ABAP Unit results, exit codes, JSON.

Under the hood

Small command surface. Serious plumbing.

The parts you would otherwise rebuild around SAP's ADT API: transports, activation, local file formats, schemas and a stable contract for agents.

Agent-native by contract

Every command speaks --json; every top-level command publishes --schema. Stable exit codes and error categories let an agent recover without parsing prose.

Files, not GUI sessions

AFF flat layout: one artifact set per object directly under src/. Namespaced objects use bracket tokens, so /UI2/CL_JSON becomes (ui2)cl_json.clas.abap.

Designed for agents

The CLI is the tool.
The agent is the driver.

An agent discovers the command surface from the binary, runs the loop with --json, and gets an actionable error code when SAP says no. No scraped docs, no guessed flags.

  • ✓Self-describing. abap <cmd> --schema --json returns arguments, options, allowed values, examples and errors.
  • ✓Stable exits. Codes 0–9 map 1:1 to error categories, so retries and escalation are deterministic.
  • ✓Progressive context. Six skills load by name and description; the full body only when the task needs it.

Quick start

From zero to your first push.

You need Node 24.22.1+, an ADT-enabled SAP system and a user with developer authorizations. The password goes to the OS keychain, not into project files.

Before you start
  • Node.js 24.22.1 or newer
  • SAP system with ADT enabled
  • Create / change / activate authorizations
Read the setup guide
01

Install the CLI

One global package. Node 24 is the only runtime requirement.

npm install -g abap-cli
02

Connect a profile

The password is stored in the OS keychain. TLS trust is managed per profile with --ca.

abap profile add DEV --url https://sap.example.com:44300 --client 100 --username DEVELOPER
03

Deploy the bundled service

Source objects work on ADT alone. DDIC, data and runtime commands need the ICF service.

abap init --profile DEV --yes abap deploy --yes
04

Run the loop

Pull an object, edit the file, push it back. No transport open? Create one with abap transport create.

abap pull ZCL_MY_CLASS abap push src/zcl_my_class.clas.abap --tr DEVK900001
