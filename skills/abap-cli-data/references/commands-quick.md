## `abap select`

Query table data read-only via the bundled ICF /data endpoint (SE16N equivalent): --table ZTAB [--fields ...] [--where ...] [--limit N] [--offset N] [--order-by ...] [--count-only]

```bash
abap select --table <name> [options]
```

| Option | Description |
| --- | --- |
| `--table <name>` | Target ABAP table or view name (e.g. ZTAB_FIXTURE). Uppercased and validated against DDIC on SAP side. |
| `--fields <csv>` | Comma-separated field names to project. Omit for all fields (large-object fields STRG/RSTR/LCHR/LRAW excluded, listed in data.excludedFields). |
| `--where <clause>` | Filter clause: FIELD OP VALUE joined by AND. Ops: = <> > >= < <= LIKE. Strings in single quotes ('' for escape), numbers bare, dates 'YYYYMMDD'. MANDT filter rejected (implicit session client). |
| `--limit <n>` | Maximum rows returned. SAP fetches limit+1 to detect truncation (data.truncated). |
| `--offset <n>` | Row offset for pagination. Deterministic pagination requires --order-by. |
| `--order-by <csv>` | Comma-separated FIELD:ASC\|DESC pairs, e.g. "ID:ASC,AMOUNT:DESC". |
| `--group-by <field>` | Aggregate: return one row per distinct value of <field> plus CNT (COUNT(*)), ordered by CNT descending. Mutually exclusive with --fields / --order-by / --offset / --count-only. |
| `--count-only` | Return only the matching row count (data.count); rows/fields omitted. |
| `--dry-run` | Plan only — print the query envelope without invoking the ICF endpoint. |
| `--json` | Emit the unified JSON envelope on stdout; --pretty-json indents. |

- Basic query with filter and limit

  ```bash
  abap select --table ZTAB_FIXTURE --where "STATUS = 'X'" --limit 50
  ```
- Projection + sort + pagination

  ```bash
  abap select --table ZTAB_FIXTURE --fields "ID,AMOUNT" --order-by "ID:ASC" --limit 20 --offset 40
  ```

## `abap fields`

List the DDIC fields of a table or view (read-only). Two modes: `abap fields <table>` enumerates the fields of one object; `abap fields --find <f1>,<f2>...` returns every table that contains those fields (reverse lookup).

```bash
abap fields <table> [--json] | abap fields --find <f1>,<f2>,...
```

| Option | Description |
| --- | --- |
| `--find <field1,field2,...>` | Reverse lookup: list every table that contains the given fields. Comma-separated. Mutually exclusive with the positional table name. |
| `--any` | With --find, return tables containing ANY of the requested fields (default: ALL). |
| `--with-text` | With --find, include DDIC short text (DD03T/DD04T) for each matched field. |
| `--as4local <A|I>` | With --find, the DDIC active/inactive version to scan. Default 'A' (active). Pass 'I' to include inactive / changed versions. |
| `--tabclass <class>` | With --find, restrict to a DDIC table class (TRANSP, VIEW, INTTAB, ...). |
| `--limit <n>` | Max matches to return (default 200, hard cap 5000). |
| `--json` | Emit a single JSON envelope (global flag). |

- Field inventory as JSON

  ```bash
  abap fields VRSD --json
  ```
- Human-readable listing

  ```bash
  abap fields VRSD
  ```

## `abap run`

Execute an ABAP class (classrun) or a static method via the bundled runner wrapper; returns stdout + exit code (read-only). The wrapper route (--method) requires a system whose ADT classrun endpoint injects method arguments; otherwise it returns WRAPPER_INPUT_UNAVAILABLE.

```bash
abap run [options] <class-name>
```

| Option | Description |
| --- | --- |
| `--method` | PUBLIC STATIC method name to invoke via ZCL_ABAP_VIBE_RUNNER. When omitted, the class is run via ADT classrun (if_oo_adt_classrun~main). NOT available on systems whose ADT classrun endpoint does not inject method arguments: the call then fails with WRAPPER_INPUT_UNAVAILABLE — use the direct classrun path (`abap run <class>`) instead. |
| `--args` | JSON object of method arguments, mapped to IMPORTING parameters (case-insensitive). Must be a JSON object, not array/null. |
| `--timeout` | Maximum execution time in ms. Wrapper path enforces server-side via cl_abap_runtime; classrun path uses ADT endpoint timeout (~5min) plus CLI-side AbortController fallback. |
| `--dry-run` | Plan only — print the request envelope without invoking ADT classrun. |
| `--json` | Emit the unified JSON envelope on stdout; --pretty-json indents. |

- Trigger classrun (no --method)

  ```bash
  abap run ZCL_MY_THING
  ```
- Invoke a static method with arguments

  ```bash
  abap run ZCL_MY_HELPER --method compute --args '{"x":3,"y":5}'
  ```

## `abap run-report`

Execute an activated REPORT and return its list output (read-only, via the bundled ICF /run/report endpoint). The report runs with DEFAULT selection values; only classic list output is captured. --format (raw\|tsv\|csv) and --param NAME=VALUE pass-through are supported.

```bash
abap run-report <report> [--variant <name>] [--format raw|tsv|csv] [--param NAME=VALUE]...
```

| Option | Description |
| --- | --- |
| `--variant <name>` | Selection variant to apply instead of the plain default values. |
| `--format <raw|tsv|csv>` | Output format. 'raw' (default) keeps SAP's list layout (with `\|` and `-----` separator bars). 'tsv' / 'csv' extract the columns to a tabular form. The transformation is client-side; the 'output' field always carries the raw SAP list so callers can switch formats without re-running the report. |
| `--param <NAME=VALUE>` | Ad-hoc selection-screen parameter, repeated. Forwarded to the SAP-side handler which echoes the list of params back in `data.params`. Apply them by changing report defaults or creating a variant. |

- Run a report and print its list

  ```bash
  abap run-report ZR_MY_REPORT
  ```
- Run with a selection variant, as JSON

  ```bash
  abap run-report ZR_MY_REPORT --variant VAR1 --json
  ```
