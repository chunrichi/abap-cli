# SM59 — HTTP 目标（SM59 HTTP Destination, RFCTYPE='G'）

SM59 事务里的 **HTTP connection to external server**（`RFCDES-RFCTYPE = 'G'`）：一个外部 HTTP(S) 目标的主机 / 端口 / 协议 / 路径前缀与描述。SM59 **没有 ADT 资源**，上游 abap-file-format 也**没有 SM59 格式**，所以本 CLI 用本地扩展格式 + 自建 ICF 端点实现。SM59 目标不是 TADIR 对象、没有 package、**无法通过 CTS 传输**——`RFCDES` 是 client-independent 的系统表（`DD02L-CONTFLAG = 'S'`），一个目标必须在每个系统分别维护。

本类型当前只覆盖 **RFCTYPE='G'**；`3` / `I` / `T` / `L` 等其它连接类型在 pull / push / delete 时返回 `SM59_TYPE_NOT_SUPPORTED`（exit 7）。UCON HTTP service、UCON RFC service（`SRFC`）与 OAuth2 profile（`OA2P`）是三个独立的后续增量，不属于本类型。

## 路由（单通道 ICF）

| 操作 | ICF 端点 |
|---|---|
| create | `POST /sap/abap_cli/sm59/<name>` |
| pull | `GET /sap/abap_cli/sm59/<name>` |
| push | `GET`（存在性探测）→ `POST /sap/abap_cli/sm59/<name>` |
| delete | `DELETE /sap/abap_cli/sm59/<name>` |

`GET /sm59`（列表）不实现；没有激活步骤（写入即生效），`push` 只更新已存在的目标。

ABAP 侧（`abap/src/zcl_abap_vibe_icf_sm59.clas.abap`）走标准维护 API 包 `SRFC_DESTAPI`，不手工解析 / 拼装 `RFCOPTIONS`：

- **读**：`SELECT SINGLE rfctype FROM rfcdes` 分类（不存在=404、非 G=拒绝），`CL_DEST_FACTORY=>create` + `CL_DEST_HTTP_EXT` getter（`server_name` / `service_number` / `path_prefix` / `ssl_active` / `description`）。
- **建**：`CL_DEST_FACTORY=>create_new( type='G', lock=abap_true )` → setters → `save( )` → `unlock( )`。
- **改**：`create( lock = abap_true )` 先 **load 全部现有属性**（含 API 认识的选项与密码 token），只覆盖 v1 字段后 `save( )`——未建模但 API 认识的属性保持原值。
- **删**：`CL_DEST_FACTORY=>delete( name )`（清 `RFCDES` / `RFCDOC` / `RFCATTRIB` / secure store；enqueue `ENQUEUE_ESRFCDES`）。不用 SM59 GUI 路径 `RFC_PREPARE_DESTINATION`。
- 权限对象 `S_RFC_ADM`：01 建 / 02 改 / 03 读 / 06 删；handler 不抑制权限检查（403 → `SM59_READ_FAILED` / `SM59_WRITE_FAILED`，exit 6）。

## 本地文件形态

```
src/
└── <name>.sm59.json
```

`sm59-v1.json` 是**本地扩展 schema**（`src/abap_cli/schema/sm59-v1.json`）：字段对应 SM59 HTTP 目标主界面。`name` 只出现在文件名 / 命令参数里（与 HTTP / TRAN 的 AFF 扁平约定一致）；`pull` 写出的文件不含 `name` / `type`（服务端身份字段），因此可以直接作为 `create` / `push` 的模板。

```json
{
  "formatVersion": "1",
  "description": "Demo HTTP destination",
  "targetHost": "example.com",
  "port": 443,
  "protocol": "HTTPS",
  "pathPrefix": "/api"
}
```

| 字段 | 必填 | 规则 / 真机映射 |
|---|---|---|
| `formatVersion` | 是 | 恒为 `"1"` |
| `description` | 否 | ≤ **72** 字符（`RFCDOC-RFCDOC1`，单行，trim）；空串允许 |
| `targetHost` | 是 | 非空、≤ 1024 字符（`RFCHOST_EXT`）；落到 `RFCOPTIONS` 的 `H=` |
| `port` | 否 | 整数 1–65535；**省略时 handler 按协议补默认值**（HTTPS 443 / HTTP 80），GET 返回整数；落到 `I=` |
| `protocol` | 是 | `HTTP` / `HTTPS`（大小写不敏感）；HTTPS ⇔ `SSL_ACTIVE`（`RFCOPTIONS` 的 `s=Y`），**不是** `W=` |
| `pathPrefix` | 否 | ≤ 255 字符（`PFADPRE`），可空；落到 `N=` |

名称上限 **32 字符**（`RFCDEST` CHAR 32），大小写不敏感（CLI 与 handler 都统一大写）；允许的字符集是 SAP 规则的子集（`A-Z 0-9 _ / . - @` 等）。`--file` 文件名必须与目标名一致：`<name>.sm59.json`。

## 命令示例

```bash
# 拉取已有 HTTP 目标（只读；其它 RFCTYPE 会报 SM59_TYPE_NOT_SUPPORTED）
abap pull SAP-SUPPORT_NOTE_DOWNLOAD --type SM59 --json

# 创建 / 覆盖（无 package、无 transport；目标直接在当前系统生效）
abap create SM59 ZCLI_SM59_DEMO --file src/zcli_sm59_demo.sm59.json --yes --json

# 修改文件后推回（push 只更新已存在的目标；不存在请用 create）
abap push src/zcli_sm59_demo.sm59.json --yes --json

# 删除
abap delete ZCLI_SM59_DEMO --type SM59 --yes --json
```

`create` / `push` 的本地校验全部在写 SAP 之前完成：schema（`sm59-v1.json`）+ 语义规则（必填、protocol、port 范围、description 长度）+ 名称规则 + 文件名匹配。`--check-only` 只做本地校验并打印计划，`--dry-run`（push）不写 SAP。

## 已知限制

1. **只有 HTTP 目标**（RFCTYPE='G'）：其它 RFCTYPE 在 pull / push / delete 时返回 `SM59_TYPE_NOT_SUPPORTED`（exit 7），不会静默当作 HTTP 处理。
2. **无 CTS 传输、无 package**：`RFCDES` 是 client-independent 系统表，目标不能被记录进传输请求。因此 `create` / `push` / `delete` **显式拒绝** `--package` / `--tr`（`TYPE_NOT_SUPPORTED`，exit 7），而不是静默忽略；迁移到另一个系统需要重新 `create`。
3. **modify 会丢掉 API 不认识的 legacy `RFCOPTIONS` 代码**：维护 API 只解码固定的 code 集合，`save` 时重建整个 `RFCOPTIONS` 串。SAP 自带的旧目标可能带有 `W=Y` / `B=N` / `C=N` / `E=N` / `T=N` / `K=Y` 等 legacy 代码——对这类目标 pull 后再 push，这些代码会消失。**自己 create 的 v1 目标 pull → push 是稳定的**。
4. **v1 不建模高级 SM59 选项**：登录方式 / 凭据、代理、SSL 应用 / 客户端证书、HTTP version / 压缩 / cookie / timeout、trust / assertion ticket、MQTT、category、UI lock、授权参数、log category、SCC。create 使用 API 默认值（登录方式 `A`=No authentication、SSL 应用 `DFAULT`、HTTP 1.0、压缩 / cookie 关闭、ICM 默认超时）；push 保留这些 API 已加载的值，只覆盖 v1 字段。需要登录数据的目标请先在 SM59 维护一次登录信息，之后的 push 不会丢。
5. **描述按语言存储**：描述写到 ICF 会话语言的 `RFCDOC` 行；GET 读会话语言行，为空时回退到任意已有语言行（因此 pull SAP 自带的英文目标仍能拿到文本）。push 只写会话语言行，其它语言行不动。
6. **GUI 确认弹窗保留名被拒绝**：SAP 对 `…_<3-8字符>_<2位数字>`、`…_TRUSTED`、`NONE[...]` 等内部保留形状会弹确认框；handler 直接返回 `SM59_NAME_INVALID`（exit 7）以保持 dialog-free。这类名字请在事务 SM59 里建。
7. **没有激活步骤**：写入即生效；`--no-activate` 被拒绝（VALIDATION_ERROR，exit 7）。
8. **`push` 只更新、不创建**：push 先 GET 探测，不存在时返回 NOT_FOUND（exit 8）并提示改用 `create`。
9. **release 与部署门槛**：需要存在 `SRFC_DESTAPI`（`CL_DEST_FACTORY` / `CL_DEST_ROOT` / `CL_DEST_HTTP` / `CL_DEST_HTTP_EXT` / `CX_DEST_API`，757 已验证）。handler 是编译期直接引用，缺该 API 的旧 release 会在 `abap deploy` 激活阶段失败、路由不存在，而不是运行时降级。部署后如果 SICF 节点缓存未刷新，可能短时间返回 unknown path，重试即可。

## 真机证据

S/4HANA 测试系统（profile `test`，ABAP release 757、client 100，CLI / ICF 服务版本 2.4.0），六阶段运行 **42/42 TC PASS**（`tests/261104001-sm59/`，本地不入库）：

- **闭环**：`create ZCLI_SM59_TC_* → pull → validate:aff → 改全部 v1 字段 → push → re-pull → delete → pull`；re-pull 与编辑值完全一致（HTTPS:443 `/api` → HTTP:8443 `/v2`）。重复 create 同一文件返回 `action=updated`（upsert 幂等）。
- **只读 pull SAP 自带目标**：`SAP-SUPPORT_NOTE_DOWNLOAD` 读到 host / 443 / HTTPS / 描述（描述走任意语言回退）；pull 前后 `RFCDES_VIEW.RFCOPTIONS` 快照一致，且从未 push / delete 该目标。
- **默认值与边界**：不带 `port` 的 HTTP / HTTPS 目标由 handler 补 80 / 443，GET 返回整数；description 72 字符通过、73 字符本地 schema 拒绝（exit 7）。
- **错误路径实测**：missing pull/push/delete → exit 8 `SM59_OBJECT_NOT_FOUND`；非 G 目标（`S4H_700@CIF_CCMS`，RFCTYPE=3）pull/push/delete → exit 7 `SM59_TYPE_NOT_SUPPORTED` 且目标未被修改；`--package` / `--tr` / `--no-activate` → exit 7（`TYPE_NOT_SUPPORTED` / `VALIDATION_ERROR`）；delete 缺 `--yes` → exit 2；本地 JSON 语法坏 → exit 2 `FILE_PARSE_ERROR`；schema 非法 → exit 7 `AFF_FIXTURE_INVALID`；SAP 保留名 shape（`ZCLI_SM59_TC_FOO_01`）→ exit 7 `SM59_NAME_INVALID`；push 不存在的目标 → exit 8（update-only）；push `--check-only` → exit 7。
- **清理**：`RFCDES` / `RFCDOC` 中 `RFCDEST LIKE 'ZCLI_SM59_TC%'` 均为 0 行（`ZCLI_SM59%` 全命名空间也为 0）；系统自带目标与 setup 快照逐字段一致，未被修改。
